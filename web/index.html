Overview

Recourse exposes a unified GraphQL endpoint at /graphql for all data operations, plus convenience REST endpoints under /api/v1/. All write operations require a valid JWT bearer token. An interactive GraphiQL IDE is available at GET /graphql.

⚡

High Performance

pgx/v5 native driver with connection pooling (25 conns), prepared statements, and statement-level timeouts on every connection.

🔐

Secure by Default

HS256 JWT tokens with configurable expiry, RBAC enforcement at the resolver level, and bcrypt password hashing.

◈

GraphQL First

Full schema with queries and mutations. Includes the embedded GraphiQL IDE for exploration without any external tooling.

🐳

Container Ready

Multi-stage Docker build producing a distroless <15MB image. Compose file brings up Postgres and the API with one command.

Quickstart

Get Recourse running locally in under 2 minutes with Docker Compose.

bash 
# 1. Clone and enter the project
cd igeTayor/recourse

# 2. Start PostgreSQL and the API
docker compose up -d

# 3. Verify health
curl http://localhost:8083/health

# 4. Open GraphiQL in browser
open http://localhost:8083/graphql

Run Natively (Go 1.25+)

bash 
# Set required environment
export DATABASE_URL="postgres://postgres:postgres@localhost:5432/recourse_db?sslmode=disable"
export JWT_SECRET="your-secure-secret-key"

# Run schema migration
psql $DATABASE_URL -f migrations/000001_create_tables.up.sql

# Start the server
go run ./cmd/server

Run Tests (with race detector)

bash 
go test -race -count=1 -v ./internal/...

Authentication

Recourse uses HS256 JWT tokens. All protected operations require an Authorization: Bearer <token> header. Tokens embed the user's role and permission set for zero-database-roundtrip authorization.

Register a User

graphql 
mutation Register($input: RegisterInput!) {
  register(input: $input) {
    token
    expiresIn
    user {
      id
      email
      role
    }
  }
}

// Variables
{
  "input": {
    "email": "alice@company.com",
    "password": "secure-password-123",
    "fullName": "Alice Johnson",
    "role": "USER"
  }
}

Login

mutation Login($input: LoginInput!) {
  login(input: $input) {
    token

  }

Role-Based Access Control

Four roles with a strict hierarchy. Admins supersede all roles. Roles are embedded in the JWT and enforced at the resolver level — no extra database round-trips.

Role Level Permissions
ADMIN 100 disputes:* users:read users:manage
ANALYST 50 disputes:read disputes:write disputes:resolve users:read
AUDITOR 30 disputes:read users:read
USER 10 disputes:read disputes:write

Disputes

Disputes represent financial transaction dispute cases. They flow through a defined lifecycle: OPEN → UNDER_REVIEW → RESOLVED | REJECTED.

graphql · Requires auth 
mutation CreateDispute($input: CreateDisputeInput!) {
  createDispute(input: $input) {
    id
    title
    amount
    currency
    status
    createdAt
    createdBy { id email role }
  }
}

{ "input": { "title": "Unauthorized charge", "description": "Card charged without consent",
               "amount": 249.99, "currency": "USD" } }
graphql · Requires auth 
query Disputes($status: DisputeStatus) {
  disputes(status: $status) {
    id
    title
    amount
    currency
    status
    createdAt
    createdBy { email fullName }
    assignee  { email fullName }
  }
}

// Filter by status — omit for all disputes
{ "status": "OPEN" }   // OPEN | UNDER_REVIEW | RESOLVED | REJECTED
graphql · Requires ANALYST or ADMIN 
mutation UpdateDispute($id: ID!, $input: UpdateDisputeInput!) {
  updateDispute(id: $id, input: $input) {
    id
    status
    resolutionNotes
    assignee { email }
    updatedAt
  }
}

{ "id": "dispute-uuid",
  "input": { "status": "RESOLVED", "resolutionNotes": "Refund issued to card ending 4242" } }
graphql · Requires ADMIN 
mutation DeleteDispute($id: ID!) {
  deleteDispute(id: $id)  # returns Boolean
}

{ "id": "dispute-uuid-to-delete" }

Users

User management operations. Most require elevated privileges.

graphql — Get current user profile 
query Me {
  me {
    id
    email
    fullName
    role
    createdAt
  }
}
graphql — List all users (ANALYST+) 
query Users {
  users {
    id email fullName role createdAt
  }
}
graphql — Update user role (ADMIN only) 
mutation UpdateUserRole($userId: ID!, $role: Role!) {
  updateUserRole(userId: $userId, role: $role) {
    id email role
  }
}

{ "userId": "user-uuid", "role": "ANALYST" }

Docker Deployment

Production-grade multi-stage build producing a minimal distroless image.

bash — One-command start 
# Start all services (API + PostgreSQL)
docker compose up -d

# View real-time logs
docker compose logs -f recourse

# Rebuild after code changes
docker compose up -d --build
